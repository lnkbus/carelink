## 4. 디자인 시안 ↔ 도메인 규칙 충돌 — 구현 전 판정 필요

시안을 그대로 구현하면 `CLAUDE.md` §6 금지 사항에 걸리는 지점입니다.
**시안이 틀렸는지, 규칙에 예외가 필요한지 사람이 정해야 합니다.**

| # | 지점 | 시안 | 충돌하는 규칙 |
|---|---|---|---|
| **C1** | SCR-303 `필요한 도움` 칩, SCR-401 `오늘 확인할 것`, SCR-403 `주의사항`, SCR-404 `근무 기록` 체크항목, SCR-506 | **"투약 확인"** 이 정형 선택 항목으로 존재 | §6-2 금지: 투약은 카탈로그에 **항목 자체가 존재하면 안 됨**. `restricted_act_keywords` 시드에 `투약`이 있어 자유 입력이면 `OPS_REVIEW` 트리거 |
| **C2** | SCR-303 `돌봄 시간` | **`24시간 상주`가 기본 선택 상태**로 조판됨 | §5.12 / `docs/12` D7: 기본값은 `H8_3SHIFT`. `H24_LIVE_IN`은 `requires_approval = true` |
| **C3** | SCR-304 간병사 카드 | `경력 3년 2개월 · **베트남**` — 국적 노출 (3명 전부) | §5.10 / D6: 국적은 통계·행정 전용. 매칭·노출 화면에서 배제 |
| **C4** | SCR-401·402·403 | 간병사에게 **환자 실명**(`김영수 어르신`) + 나이·성별 노출 | `docs/11` §3.2: 간병사에게는 병실·필요 지원·주의사항만. 실명 ❌ |

C1이 가장 무겁습니다. 5개 화면에 걸쳐 있고, 시안대로 만들면 의료행위를 플랫폼이
정형 항목으로 승인하는 형태가 됩니다.

## 5. 착수 전 법무·노무 선행 항목 (`docs/12` §3)

**U1~U4가 나머지를 전부 막고 있습니다. 개발과 병행이 아니라 선행입니다.**

| # | 결정 | 막히면 | 기한 |
|---|---|---|---|
| U1 | 도급인가 파견인가 — 지휘·명령권 설계 | 사업 구조 전체 | 즉시 |
