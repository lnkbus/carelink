# 15. 맥북에서 실행하기

호스트에 필요한 것은 **Docker 하나뿐**입니다. `psql` · `node` · `flutter` ·
`pnpm` 전부 컨테이너 안에 있습니다.

---

## 1. 준비 (한 번만)

[Docker Desktop](https://www.docker.com/products/docker-desktop/)을 설치하고
실행합니다. Apple Silicon(M1~M4)과 Intel 맥 모두 됩니다 — 쓰는 이미지가
전부 arm64를 지원해서 에뮬레이션이 걸리지 않습니다.

```bash
git clone <저장소> carelink
cd carelink
git checkout claude/new-workforce-platform-2m96y8
```

---

## 2. 실행

```bash
bash infra/local/start.sh
```

빌드 → 기동 → 데모 데이터까지 한 번에 합니다. **첫 실행은 5~10분**
걸립니다(이미지 내려받기 + 빌드). 두 번째부터는 1분 안쪽입니다.

끝나면 이렇게 뜹니다:

```
  http://localhost:3100   웹 — 로그인하면 역할이 갈라 줍니다
                          운영자 → /admin · 기관 담당자 → /org
```

### 앱까지 보려면

```bash
bash infra/local/start.sh --mobile
```

Flutter 이미지가 2GB대라 **첫 빌드에 10~20분** 더 걸립니다. 그래서 기본에서
빼 두었습니다. 붙으면 `:3300`이 열립니다 — 후보자 · 간병사 · 보호자가
한 앱이고, 로그인한 계정의 역할이 셸을 정합니다.

> 이건 **검증용 웹 빌드**입니다. 실제 배포는 앱스토어이고, 터치 타깃·글꼴
> 크기는 실기기에서 최종 확인해야 합니다 (docs/14 §3-3).

## 3. 로그인

**비밀번호가 없습니다.** 번호를 넣고 `인증번호 받기`를 누르면 개발
환경에서는 인증번호가 화면에 그대로 표시됩니다.

| 역할 | 번호 | 어디서 |
|---|---|---|
| 운영자 | `01011110001` | :3100 → `/admin` |
| 기관 (검증 완료) | `01022220001` | :3100 → `/org` |
| 기관 (검증 대기) | `01022220002` | :3100 → `/org` |
| 후보자 | `01033330001` | :3300 |
| 후보자 (해외 거주) | `+84912345678` | :3300 |
| 보호자 | `01055550001` | :3300 |
| 간병사 | `01044440001` | :3300 |

주소는 둘뿐입니다. 로그인하면 역할이 어디로 갈지 정합니다 — 웹은
`middleware.ts`가, 앱은 `AppState.activeRole`이 (CLAUDE.md §4.1).

### 해외 거주 후보자

`+84912345678`로 로그인해 보세요. **한국 번호가 없는 사람이 직접 가입하는
경로**입니다 (2026-08-21 확정 · docs/08 E·F 세그먼트 — 현지 고려인, 베트남
양성대학). 번호는 E.164로 저장되고, 표기가 달라도(`+84 91 234 5678`,
`0084912345678`) 같은 계정으로 붙습니다.

> 한국 번호는 `+8210…`으로 저장되지만 화면에는 `010…`으로 보입니다.
> 자기 번호를 못 알아보면 로그인한 계정이 자기 것인지 확신할 수 없습니다.

**SMS 발송은 아직 붙어 있지 않습니다.** 이 스택은 인증번호를 화면에
띄우고, 실제 운영에서는 국가별 발송 계약이 선행돼야 합니다.

### 로그아웃 · 계정 바꾸기

| 화면 | 어디에 있나 |
|---|---|
| 운영 콘솔 · 기관 웹 | 사이드바 맨 아래. 지금 로그인한 번호가 함께 표시됩니다 |
| 보호자 웹 | 홈 앱바의 `내 정보` → 맨 아래 |
| 후보자 앱 | 하단 탭 `내 정보` → 맨 아래 |
| 간병사 앱 | 홈 앱바의 사람 아이콘 → `내 정보` 맨 아래 |

FIELD 앱 세 개는 **로그아웃 자리가 같습니다 — '내 정보' 화면 맨 아래.**
앱바나 홈에 두면 근무 중에 뒤로가기 대신 눌리고, 그러면 병실 앞에서
인증번호를 기다리게 됩니다. 셋 다 확인 한 단계를 거칩니다.

로그아웃은 쿠키만 지우는 게 아니라 **서버에서 refresh 토큰을 폐기**합니다.
그러지 않으면 14일 동안 그 토큰으로 다시 로그인할 수 있습니다.

### 여러 역할을 나란히 놓고 비교하기

같은 후보자가 기관에는 익명으로, 운영자에게는 실명으로 보이는지 —
이 확인이 이 플랫폼에서 가장 자주 하는 일입니다.

**웹(:3100)은 세션이 한 벌입니다.** 운영 콘솔과 기관 웹이 한 서비스이므로
쿠키(`cl_at`)도 하나입니다. 운영자와 기관 담당자를 동시에 열려면
**브라우저 프로필을 나누거나 시크릿 창**을 쓰세요.

> 나눠 두었을 때는 쿠키 이름을 `cl_at_admin` / `cl_at_org`로 갈랐습니다.
> 쿠키가 포트를 구분하지 않아, 같은 이름이면 기관 웹에 로그인하는 순간
> 운영 콘솔이 로그아웃됐기 때문입니다. 이제 한 서비스라 로그인도 한 번입니다.

**앱(:3300)은 웹과 포트가 달라 그대로 동시에 열립니다.** Flutter 웹은
브라우저 저장소를 쓰고 그 저장소는 포트까지 구분합니다.

앱 안에서 역할을 바꿀 때는 로그아웃하지 않아도 됩니다 — 역할이 둘 이상인
계정이면 **내 정보 → 역할 바꾸기**가 보입니다. 역할이 하나뿐인 계정에는
보이지 않습니다.

## 4. 무엇을 눌러 볼 것인가

이 플랫폼이 파는 것은 **막는 능력**입니다. 되는 것보다 안 되는 것을
확인하는 편이 빠릅니다.

### 개인정보 게이트 — 가장 중요한 경로

1. `01022220001`(검증 완료)로 :3100 → 후보자 검색 → 이름이 `CD-1001` 형태
2. 로그아웃 후 `01022220002`(검증 대기)로 다시 → **같은 목록이 더 잠겨 있음**
3. 다른 탭에서 :3100(운영자)을 열어 같은 후보자를 보면 실명이 보입니다.
   로그아웃 없이 나란히 비교됩니다 (§3 '세 역할을 동시에')
4. 어느 쪽에서도 **국적·체류자격 코드는 나오지 않습니다** (§6-12 · §6-13)

### 취업 가능 여부 — 세 상태

기관 웹 후보자 검색의 `취업 가능` 열:

| 후보 | 표시 | 왜 |
|---|---|---|
| CD-1003 | ✓ 가능 | H-2 방문취업. 병원간병 허용 |
| CD-1002 | ! 확인 중 | 내국인. **불가가 아니라 판정 전입니다** |
| CD-1001 | ✕ 불가 | E-9 비전문취업은 지정 업종만 |

가운데를 '불가'로 표시하면 판정 전인 사람이 취업할 수 없는 사람으로
보이고, 기관이 그를 거릅니다. 그래서 셋으로 나눴습니다.

### 업무범위 — 감지는 거절이 아닙니다

1. :3300 앱 → 보호자로 로그인 → 간병 신청 → 특이사항에 **"인슐린 주사를 놓아주세요"**
2. 신청이 **취소되지 않고** 확인 화면으로 넘어갑니다
3. 화면에 "신청이 취소된 것이 아닙니다"가 보입니다
4. :3100 운영 콘솔 처리 큐에 그 요청이 올라와 있습니다

자동 거절하면 보호자가 표현을 바꿔 우회하고, 그러면 간병사에게 그대로
전달됩니다 (§6-15).

### 24시간 상주는 아예 선택지에 없습니다

:3300 간병 신청 화면의 교대 방식에 24시간 항목이 없습니다. 대신 안내가
있습니다 — *"한 분이 24시간 상주하는 방식은 운영하지 않습니다."*

### 간병사 화면에 환자 이름이 없습니다

`01044440001`로 :3300 → 오늘 근무 → 근무 시작. 병원·병실·필요한 지원·
주의사항은 나오지만 **환자 실명·나이·진단명은 어디에도 없습니다**
(docs/11 §3.2).

병실 QR 코드가 필요합니다. 시드 실행 시 마지막 줄에 출력됩니다.
틀린 값을 넣으면 거부됩니다.

### 클리어런스 6종

`01044440003` 간병사는 6개 중 5개만 통과했습니다. 보호자 화면 매칭
결과에서 **빠져 있습니다** — 운영자도 예외 처리할 수 없습니다 (§5.11).

## 4-1. 무언가 안 될 때 — 로그부터

화면이 조용히 로그인으로 되돌아가면 **서버 로그에 이유가 있습니다.**
API는 4xx·5xx를 전부 한 줄로 남깁니다 (운영 모드에서도 켜져 있습니다):

```bash
docker compose logs -f api            # 실시간
docker compose logs api --tail 100    # 최근 100줄
docker compose logs api | grep WARN   # 막힌 요청만
```

읽는 법:

```
403 GET /api/v1/admin/dashboard → IAM_ROLE_FORBIDDEN {"required":"ADMIN"}
    ↑    ↑                        ↑                    ↑
   상태  경로                   도메인 코드          사유
```

`IAM_ROLE_FORBIDDEN`은 **로그인은 됐지만 권한이 없다**는 뜻입니다 — 번호를
다시 넣어도 결과가 같습니다. 이제 로그인 화면에도 그렇게 적힙니다.

## 5. 게이트가 살아 있는지 한 번에 확인

```bash
docker compose run --rm tools smoke
```

29개 항목이 통과해야 합니다. 막혀야 할 것이 막히는지만 봅니다 —
클리어런스, 국적 비노출, 의료행위 카탈로그, 3단계 확정, QR, append-only,
파견 허가번호, 24시간 차단, 연속 교대 차단.

**하나라도 실패하면 배포하지 마세요.** 전부 "뚫리면 사업이 끝나는" 쪽입니다.

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| `Docker가 실행 중이 아닙니다` | Docker Desktop 미실행 | 실행 후 재시도 |
| 포트 5432가 이미 사용 중 | 맥에 Postgres가 이미 떠 있음 | 컴포즈는 `55432`를 씁니다. 충돌이면 `DB_PORT=55433 bash infra/local/start.sh` |
| 인증번호가 안 보임 | 30초 재발송 쿨다운 | 잠시 후 다시. 또는 `docker compose run --rm tools demo` (쿨다운을 지웁니다) |
| 첫 빌드가 너무 김 | Flutter 이미지 2GB대 | `--mobile` 없이 먼저 웹 4종만 |
| 데이터가 꼬임 | — | `docker compose down -v` 후 다시 시작 (DB가 초기화됩니다) |
| `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY` | pnpm 10이 node_modules 삭제 확인을 묻는데 도커에 TTY가 없음 | 고쳐졌습니다 (`ENV CI=true`). 옛 커밋이면 `git pull` |
| `service "migrate" didn't complete successfully: exit 3` | 이미 적용된 스키마에 `0001_init.sql`을 다시 실행 | 고쳐졌습니다 (`infra/migrations/apply.sh`가 건너뜁니다). 옛 커밋이면 `git pull` |
| 인증번호가 화면에 안 보임 | API가 `AUTH_EXPOSE_OTP_CODE` 없이 떠 있음. 이 스택엔 SMS가 없어 화면 표시가 유일한 전달 경로입니다 | 고쳐졌습니다. 옛 커밋이면 `git pull && docker compose up -d --build api`. 확인: `docker compose exec api printenv AUTH_EXPOSE_OTP_CODE` |
| 시드가 `invalid input syntax for type uuid: ""`를 쏟아냄 | 위와 같은 원인 — 로그인이 안 돼 user_id가 빈 값 | `docker compose down -v && bash infra/local/start.sh` |
| 로그인해도 조용히 로그인 화면으로 되돌아옴 | 이전 DB의 번호가 E.164 이전 형식이라 계정이 갈라짐 | 고쳐졌습니다 (`0003_phone_e164.sql`이 자동 적용). 옛 커밋이면 `git pull && docker compose up -d --build` |
| 권한 오류 원인을 모르겠음 | — | `docker compose logs api \| grep WARN` — 4xx가 도메인 코드와 함께 한 줄로 남습니다 (§4-1) |
| 빌드가 중간에 멈춤 | Docker Desktop 메모리 부족 | 설정 → Resources → Memory를 4GB 이상으로 |
| 화면이 비어 있음 | 데모 데이터 없음 | `docker compose run --rm tools demo` |
| 데모를 다시 넣고 싶음 | 이미 있으면 건너뜁니다 (중복 방지) | `docker compose down -v` 후 다시 시작 |

## 8. 코드를 고치면서 볼 때

컨테이너를 매번 다시 빌드하면 느립니다. 이때는 호스트에 도구를 깝니다.

```bash
brew install node@22 pnpm postgresql@16 redis
brew install --cask flutter          # 앱까지 볼 때만

docker compose up -d db redis        # DB·Redis만 컨테이너로
pnpm install
DATABASE_URL=postgres://carelink:carelink@127.0.0.1:55432/carelink pnpm db:migrate
DATABASE_URL=postgres://carelink:carelink@127.0.0.1:55432/carelink pnpm db:seed

pnpm --filter @carelink/api start:dev
pnpm --filter @carelink/web dev
```

시드·스모크 스크립트는 호스트에서도 그대로 돕니다 — GNU 전용 문법
(`date -d` · `xargs -r`)을 쓰지 않고, bash 3.2(맥 기본)에서 동작합니다.

```bash
pnpm demo  "http://127.0.0.1:3000/api/v1" "postgres://carelink:carelink@127.0.0.1:55432/carelink"
pnpm smoke "http://127.0.0.1:3000/api/v1" "postgres://carelink:carelink@127.0.0.1:55432/carelink"
```
