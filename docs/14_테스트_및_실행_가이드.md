## 1. 한 번에 띄우기

```bash
bash infra/local/start.sh     # 권장 — 빌드·기동·데모 데이터를 한 번에
docker compose up -d --build  # 직접 띄울 때
```

**맥북에서 처음 돌리신다면 `docs/15_맥북_로컬_실행.md`를 보세요.** 포트 충돌,
Flutter 빌드 시간, 호스트 도구 없이 시드 돌리는 방법이 정리돼 있습니다.

서비스는 **둘**입니다 — DESK 웹 한 벌과 FIELD 앱 한 벌. 역할별로 주소를
나누지 않습니다 (CLAUDE.md §4.1).

| 주소 | 무엇 | 화면 |
|---|---|---|
| http://localhost:3000/api/v1 | API | — |
| http://localhost:3100 | 웹 | 로그인 후 역할이 갈라 줍니다 |
| ↳ `/admin` | 운영 콘솔 | SCR-501·502·503·504·507·508·509·510·511 |
| ↳ `/org` | 기관 웹 | SCR-201·202·203·204·205 |
| http://localhost:3300 | 앱 (웹 빌드) | 로그인 후 역할이 셸을 정합니다 |
| ↳ 후보자 셸 | | SCR-101~110 |
| ↳ 간병사 셸 | | SCR-401~404 |
| ↳ 보호자 셸 | | SCR-301~307 |

스키마와 시드는 `migrate` 컨테이너가 한 번 돌고 끝납니다. API는 그것이 성공한 뒤에 뜹니다.

### 데모 데이터

빈 화면은 동작을 판단할 수 없습니다. 스택이 뜬 뒤 한 번 실행하세요.

```bash
pnpm demo        # 또는: bash infra/smoke/demo-seed.sh
```

| 역할 | 번호 | 어디서 | 무엇이 보이나 |
|---|---|---|---|
| 운영자 | `01011110001` | 웹 → `/admin` | 트랙별 파이프라인 · 처리 큐 2건 · 산업/트랙 관리 |
| 기관 (검증완료) | `01022220001` | 웹 → `/org` | 후보자 4명 · 채용 요청 1건 · 지원 1건 |
| 기관 (검증대기) | `01022220002` | 웹 → `/org` | **같은 후보자가 잠겨 보입니다** — 게이트 비교용 |
| 후보자 | `01033330001` | 앱 | 배치 준비 · 서류 2건 (1건 D-20 카운트다운) |
| 후보자 (해외 거주) | `+84912345678` | 앱 | **한국 번호 없이 가입** · 베트남어 · 입국 전 |

| 승인 대기 | `01077770001` | 웹 → `/pending` | 기관 신규 등록 — 운영자가 승인하면 `ORG_ADMIN` |
| 승인 대기 | `01077770002` | 웹 → `/pending` | 서울중앙요양병원 합류 — `01022220001`이 `/org/members`에서 승인 |
| 승인 대기 | `01077770003` | 웹 → `/pending` | 파트너 제휴 — 운영자만 승인 가능 |

**주소를 외울 필요가 없습니다.** 웹은 `:3100`만 알면 되고, 로그인하면
운영자는 `/admin`으로 기관 담당자는 `/org`로 갑니다. 앱도 `:3300` 하나이고
로그인한 계정의 역할이 셸을 정합니다. 역할이 둘 이상인 계정은 내 정보
화면에서 전환합니다.

**비밀번호가 없습니다.** 번호를 넣고 `인증번호 받기`를 누르면 데모
스택에서는 인증번호가 화면에 그대로 표시됩니다 (`AUTH_EXPOSE_OTP_CODE=true`).

번호는 **E.164로 저장**됩니다. `01011110001`로 넣든 `+82 10 1111 0001`로
넣든 같은 계정입니다. 화면에는 익숙한 `010…`으로 되돌려 보여 줍니다.

후보자 4명의 값이 서로 다릅니다. 지역·고용형태·근무 가능일이 전부 같으면
필터를 걸어도 결과가 안 바뀌고 매칭 점수도 동점으로 나와서, **화면이 도는
것만 확인되고 로직이 도는지는 확인되지 않습니다.**

| 후보 | 체류자격 | 취업 가능 | 트랙 | 지역 | 근무 가능 | 왜 이렇게 뒀나 |
|---|---|---|---|---|---|---|
| CD-1001 | E-9 | ✕ 불가 | 병원간병 | 경기 안산 | 즉시 | 비전문취업은 지정 업종만. 병원간병은 대상이 아닙니다 |
| CD-1002 | 없음(내국인) | ! 확인 중 | 요양보호 | 서울 노원 | +14일 | **불가가 아닙니다.** 아직 판정 전입니다 |
| CD-1003 | H-2 | ✓ 가능 | 병원간병 + 요양보호 | 충북 청주 | +30일 | 방문취업(고려인 · docs/08). 트랙 두 개를 겹쳐 가진 경우 |
| CD-1004 | 없음(미정) | ! 확인 중 | 요양보호 | 베트남 하노이 | +90일 | **해외 거주.** 국제번호로 직접 가입한 경로 (docs/08 E·F) |

서류도 사람마다 다릅니다 — 검증 완료 · 검토 중 · 반려 · 만료 임박(D-20).
전부 VERIFIED면 만료 카운트다운도 반려 안내도 화면에 나타나지 않습니다.

간병사 3명 중 `01044440003`은 클리어런스를 5/6만 채웠습니다 — 매칭
결과에서 빠지는 것을 확인할 수 있습니다 (§5.11).

**Flutter 앱은 빌드 컨텍스트가 리포 루트입니다.** 공용 FIELD
패키지(`packages/field_ui`)가 path 의존이라 앱 디렉터리만으로는 `pub get`이
실패합니다. `docker compose`가 알아서 처리하지만, 직접 `docker build`를
돌릴 때는 루트에서 `-f apps/mobile/Dockerfile .` 형태로 주세요.

**정리**: `docker compose down -v` (`-v`를 빼면 DB가 남습니다)

## 2. 로그인 방법 — 개발 환경

비밀번호가 없습니다. 휴대폰 OTP만 씁니다 (README §4-2 S1 확정).

개발 환경에서는 `POST /auth/otp/send` 응답에 `devCode`가 함께 옵니다.
운영에서는 이 필드가 내려오지 않습니다.

```bash
# 1) 인증번호 발급 (아무 번호나 됩니다 — 신규 번호면 계정이 생성됩니다)
curl -s -X POST http://localhost:3000/api/v1/auth/otp/send \
  -H 'content-type: application/json' -d '{"phone":"01011112222"}'
# → {"expiresInSeconds":180,"devCode":"123456"}
```

화면에서는 인증번호 입력란 아래에 `DEV 123456`이 함께 뜹니다. 그대로 넣으면 됩니다.

### 역할 부여

가입 직후에는 역할이 없습니다. 화면별로 필요한 역할이 다릅니다.

```bash
# 후보자 — 앱에서 자동으로 붙습니다. 수동으로 하려면:
curl -s -X POST http://localhost:3000/api/v1/auth/roles \
  -H "authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"role":"CANDIDATE","makePrimary":true}'

# 운영자 · 기관 담당자 — 승인이 필요하므로 DB에 직접 넣습니다 (개발 전용)
docker compose exec db psql -U carelink -d carelink -c \
  "INSERT INTO user_roles (user_id, role, is_primary, approved_at)
   VALUES ('<USER_ID>','ADMIN',true,now());"

docker compose exec db psql -U carelink -d carelink -c \
  "INSERT INTO user_roles (user_id, role, organization_id, is_primary, approved_at)
   VALUES ('<USER_ID>','ORG_MEMBER','<ORG_ID>',true,now());"
```

역할을 넣은 뒤에는 **토큰을 새로 받아야 합니다** — 역할은 발급 시점에 토큰에 박힙니다.
화면에서는 로그아웃 후 다시 로그인하면 됩니다.

## 3. 후보자 앱 (Flutter) 테스트 방안

컨테이너에는 기기도 에뮬레이터도 없습니다. 그래서 검증을 **4단계로 나눕니다.**
각 단계가 잡는 것과 놓치는 것이 다릅니다.

### 3-1. 단위·위젯 테스트 — 지금 CI에서 돌아갑니다

```bash
cd apps/mobile
flutter test
```

**잡는 것** (현재 23건)

| 테스트 | 무엇을 막는가 |
|---|---|
| `i18n_test.dart` | 4개 언어 중 하나라도 키가 빠지면 실패. 빠진 키는 그 언어 사용자 화면에 `jobs.apply`로 보이고, 발견하는 사람은 그 사용자뿐 |
| | 한국어를 복사해 둔 미번역 문구 검출 |
| | 버튼 라벨이 32자를 넘는지 (어느 언어든 잘림) |
| `field_constraints_test.dart` | 본문 16px·터치 타깃 48px·주요 버튼 56px 미만 |
| | 만료 임계값 (D-90/D-30) 회귀 |
| | `StatusPill`이 아이콘 없이 색만으로 상태를 전달하는지 |
| | 러시아어 최장 라벨에서 버튼 오버플로 |

**놓치는 것**: 실제 터치 정확도, 시스템 글꼴 확대 조합, 저사양 기기 성능, 카메라·파일 선택.

### 3-2. 웹 빌드 — 화면 흐름과 API 연동

```bash
# Docker로 (권장)
docker compose up -d mobile-web       # → http://localhost:3300

# 또는 로컬에서
cd apps/mobile
flutter run -d chrome --dart-define=CARELINK_API_URL=http://localhost:3000/api/v1
```

브라우저 개발자도구에서 **기기 에뮬레이션(402×1096)**으로 보면 FIELD 프레임과 같습니다.

**잡는 것**: 화면 전환, API 연동, 4개 언어 전환, 에러 문구, 빈 목록 상태.
**놓치는 것**: 실제 터치 타깃 체감, 네이티브 저장소(`flutter_secure_storage`는 웹에서
localStorage로 폴백 — **웹 빌드는 토큰 보안을 검증하지 못합니다**), 푸시 알림, 오프라인.

### 3-3. 안드로이드 실기기 — FIELD 규격 최종 확인

```bash
cd apps/mobile
flutter build apk --release --dart-define=CARELINK_API_URL=http://<호스트IP>:3000/api/v1
# → build/app/outputs/flutter-apk/app-release.apk
```

에뮬레이터에서 호스트는 `10.0.2.2`입니다 (`localhost`가 아닙니다 — 기본값이 그렇게 되어 있습니다).
실기기라면 같은 네트워크의 호스트 IP를 넣고, API의 `CORS_ORIGINS`에 그 주소를 추가하세요.

**여기서만 확인 가능한 것 — 반드시 체크**

- [ ] 40~65세 사용자가 한 손으로 홈 → next_action → 서류 업로드까지 도달하는가
- [ ] 시스템 글꼴을 최대로 키웠을 때 레이아웃이 깨지지 않는가 (앱은 1.6배까지 허용)
- [ ] 4개 언어 각각에서 버튼 텍스트가 잘리지 않는가 (특히 러시아어 — 실측 4.1배)
- [ ] `flutter_secure_storage`가 실제로 Keystore를 쓰는가 (재설치 후 세션이 사라지는지)
- [ ] 저사양 기기에서 목록 스크롤이 끊기지 않는가

### 3-4. 통합 테스트 — 실기기 자동화

`integration_test` 패키지로 실기기에서 흐름 전체를 돌립니다. **아직 작성하지 않았습니다** —
기기 없이 쓰면 검증되지 않은 테스트가 쌓입니다. 기기가 준비된 시점에 아래 흐름부터 쓰세요.

```
로그인 → 역할 선택 → 홈(next_action 1개 확인) → 트랙 선택
     → 서류 업로드 → 여정에서 두 축이 분리돼 보이는지 → 일자리 지원
```

```bash
flutter test integration_test/ -d <device-id>
```

### 3-5. 간병사 · 보호자 셸 테스트 방안

앱이 하나이므로 테스트도 한 곳입니다. 셸이 달라도 토큰·API 클라이언트·
위젯이 `packages/field_ui`로 공용이라 FIELD 규격 검증은 한 번이면 됩니다.

```bash
cd apps/mobile
flutter test          # 42건
flutter analyze
```

| 파일 | 무엇을 강제하나 |
|---|---|
| `test/i18n_test.dart` | 4개 언어 키 집합 일치 · 확장률 · 버튼 라벨 길이 |
| `test/field_constraints_test.dart` | 16px 하한 · 48px 터치 타깃 · 색+아이콘+텍스트 3중 표현 |
| `test/caregiver_test.dart` | 환자 실명·진단명 키 부재 · 수락≠확정 · 카탈로그에 의료행위 없음 |
| `test/guardian_test.dart` | 간병사 국적·실명 모델 부재(§6-21) · 금액 부재(§6-8) · 24시간 안내 문구 |

간병사 앱 테스트가 특별히 확인하는 것:

| 무엇 | 왜 |
|---|---|
| 환자 신원 키가 **사전에 없다** | 사전에 없으면 화면에 그릴 수도 없습니다 (docs/11 §3.2) |
| 모델이 `patientName`을 받지 않는다 | API가 실수로 필드를 늘려도 앱은 그리지 않습니다 |
| 서비스 카탈로그 6종이 전부 번역돼 있다 | 빠지면 `MEAL_SUPPORT`가 화면에 그대로 뜹니다 |
| 카탈로그 라벨에 의료행위가 **없다** | `MEDICATION`·`INJECTION`이 생기지 않았는지 반대 방향으로 확인 (§6-2) |
| `ACCEPTED`는 오늘 근무가 아니다 | 수락은 확정이 아닙니다 (§6-4) |

### 실기기에서 반드시 볼 것

웹 빌드로는 안 잡히는 것들입니다.

1. **QR 입력 필드** — 병실 코드를 넣었을 때 시작 버튼이 실제로 활성화되는지.
   웹에서 이게 안 돼서 근무를 시작할 수 없었던 적이 있습니다 (F-21).
2. **장갑 낀 손** — 간병사는 위생장갑을 낀 채로 화면을 만집니다. 48px
   타깃이 실제로 눌리는지 확인하세요.
3. **병실 조명** — 야간 근무 시 병실은 어둡습니다. 저조도에서 대비가
   충분한지 봅니다.
4. **한 손 조작** — 다른 손으로 환자를 부축한 상태를 가정하세요.

## 3-6. 스모크 테스트 — 게이트가 살아 있는가

```bash
pnpm smoke                                    # API가 :3000에 떠 있어야 합니다
bash infra/smoke/smoke.sh <API_URL> <DB_URL>  # 주소를 바꾸려면
```

**기능이 되는지가 아니라 막혀야 할 것이 막히는지**를 봅니다. 기능은 단위
테스트가 보지만, 게이트는 여러 모듈이 맞물려야 성립해서 실환경에서만
드러납니다. 26개 항목이 통과해야 합니다.

| 검사 | 근거 |
|---|---|
| 역할 없는 사용자는 운영자 경로 403 | §5.2 |
| 클리어런스 5/6인 인력은 매칭에서 제외 | §5.11 |
| 간병사 카드에 국적·실명·연락처 없음 | §6-21 · §5.10 |
| 의료행위 요구가 거절이 아니라 `OPS_REVIEW`로 | §6-15 |
| 카탈로그에 의료행위 항목 자체가 없음 | §6-2 |
| 승인 없는 24시간은 매칭 차단 | §5.12 |
| 간병사가 스스로 확정할 수 없음 | §6-4 |
| 간병사 뷰에 환자 신원 없음 (병실은 나감) | docs/11 §3.2 |
| 간병사가 **자기 배정은 볼 수 있음** | scope가 과하게 닫힌 쪽 (F-20) |
| 다른 병실 QR로 체크인 불가 | §6-3 |
| `service_logs`·`audit_logs`를 DB가 막음 | §5.4 |
| 허가번호 없는 파견 차단 | 파견법 §7 |
| 요건 없는 트랙은 열리지 않음 | SCR-507 |
| 24시간 상주는 집계에서 제외 | U5 · §6-8 |

**실패하면 배포하지 마세요.** 여기 있는 것은 전부 "뚫리면 사업이 끝나는"
쪽입니다.

## 4. 백엔드·웹 테스트

### 업무범위 게이트 수동 확인

두 번째로 중요한 경로입니다. 감지는 **거절이 아니라 검토 트리거**입니다 (§6-15).

1. 앱에서 보호자로 로그인 → 간병 신청 → 특이사항에 "인슐린 주사를 놓아주세요" 입력
2. 신청이 **취소되지 않고** 확인 화면으로 넘어감 → 상태가 `OPS_REVIEW`
3. 화면에 "신청이 취소된 것이 아닙니다"가 보여야 함
4. 운영자 콘솔에서 해당 요청이 검토 큐에 있음
5. 운영자가 `MATCHING`으로 되돌리면 매칭이 다시 돌아감
6. 앱에서 간병사로 로그인 → 그 배정을 열면 **업무범위 경고가 화면 맨 위에** 보임

6번이 핵심입니다. 경고가 아래에 있으면 간병사가 시작을 누르고 나서 보게
되고, 그때는 이미 병실 안입니다.

### 개인정보 게이트 수동 확인

이 플랫폼에서 가장 중요한 경로입니다. 배포 전마다 확인하세요.

1. 기관 담당자로 로그인 (검증 **대기** 기관) → `/candidates/{id}` → 이름이 "기관 검증 후 열립니다"
2. 운영자로 기관을 `VERIFIED`로 변경 → 다시 조회 → 이름이 "면접 수락 후 열립니다"
3. 후보자가 면접 요청을 수락 → 다시 조회 → **그 후보자만** 실명·연락처가 열림
4. 같은 목록의 다른 후보자는 여전히 잠겨 있어야 함

4번이 핵심입니다. 승격이 뷰어 단위로 잘못 붙으면 한 명을 수락받은 기관이
전 후보자의 실명을 보게 됩니다.

## 5. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 웹에서 API 호출이 CORS로 막힘 | 출처가 허용 목록에 없음 | `CORS_ORIGINS` 환경변수에 추가 후 API 재시작 |
| 로그인은 되는데 화면이 비어 있음 | 역할이 없음 | 역할 부여 후 **재로그인** (토큰에 박혀 있음) |
| 에뮬레이터에서 API 연결 실패 | `localhost`는 에뮬레이터 자신 | `10.0.2.2` 사용 |
| `devCode`가 안 옴 | `NODE_ENV=production` | 개발 환경에서만 내려옵니다 |
| OTP 재발송이 막힘 | 같은 번호 30초 쿨다운 | 기다리거나 `redis-cli DEL otp:cooldown:<번호>` |
| Flutter 웹이 백지 | CanvasKit이 CDN에서 매달림 | `--web-renderer html`로 빌드 (docs/13 D-11) |
| `docker build`가 `pub get`에서 실패 | 컨텍스트가 앱 디렉터리 | 리포 루트에서 `-f apps/<앱>/Dockerfile .` |
| 병원 목록이 비어 있음 | 배정 가능한 간병사가 0명 | 공급 없는 병원은 노출하지 않습니다 (SCR-302). 클리어런스 6종을 통과시키세요 |
| OTP 재발송이 막힘 | 30초 레이트 리밋 | 기다리거나 다른 번호 사용 |
| 후보자 목록이 비어 있음 | 시드에는 후보자가 없음 | 앱으로 가입하거나 API로 생성 |
