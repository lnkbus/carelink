## 2. 로그인 방법 — 개발 환경

비밀번호가 없습니다. 휴대폰 OTP만 씁니다 (README §4-2 S1 확정).

개발 환경에서는 `POST /auth/otp/send` 응답에 `devCode`가 함께 옵니다.
운영에서는 이 필드가 내려오지 않습니다.

```bash
# 1) 인증번호 발급 (아무 번호나 됩니다 — 신규 번호면 계정이 생성됩니다)
curl -s -X POST http://localhost:3000/api/v1/auth/otp/send \
  -H 'content-type: application/json' -d '{"phone":"01011112222"}'
# → {"expiresInSeconds":180,"devCode":"123456"}
```

화면에서는 인증번호 입력란 아래에 `DEV 123456`이 함께 뜹니다. 그대로 넣으면 됩니다.

### 역할 부여

가입 직후에는 역할이 없습니다. 화면별로 필요한 역할이 다릅니다.

```bash
# 후보자 — 앱에서 자동으로 붙습니다. 수동으로 하려면:
curl -s -X POST http://localhost:3000/api/v1/auth/roles \
  -H "authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"role":"CANDIDATE","makePrimary":true}'

# 운영자 · 기관 담당자 — 승인이 필요하므로 DB에 직접 넣습니다 (개발 전용)
docker compose exec db psql -U carelink -d carelink -c \
  "INSERT INTO user_roles (user_id, role, is_primary, approved_at)
   VALUES ('<USER_ID>','ADMIN',true,now());"

docker compose exec db psql -U carelink -d carelink -c \
  "INSERT INTO user_roles (user_id, role, organization_id, is_primary, approved_at)
   VALUES ('<USER_ID>','ORG_MEMBER','<ORG_ID>',true,now());"
```

역할을 넣은 뒤에는 **토큰을 새로 받아야 합니다** — 역할은 발급 시점에 토큰에 박힙니다.
화면에서는 로그아웃 후 다시 로그인하면 됩니다.

## 3. 후보자 앱 (Flutter) 테스트 방안

컨테이너에는 기기도 에뮬레이터도 없습니다. 그래서 검증을 **4단계로 나눕니다.**
각 단계가 잡는 것과 놓치는 것이 다릅니다.

### 3-1. 단위·위젯 테스트 — 지금 CI에서 돌아갑니다

```bash
cd apps/mobile-candidate
flutter test
```

**잡는 것** (현재 23건)

| 테스트 | 무엇을 막는가 |
|---|---|
| `i18n_test.dart` | 4개 언어 중 하나라도 키가 빠지면 실패. 빠진 키는 그 언어 사용자 화면에 `jobs.apply`로 보이고, 발견하는 사람은 그 사용자뿐 |
| | 한국어를 복사해 둔 미번역 문구 검출 |
| | 버튼 라벨이 32자를 넘는지 (어느 언어든 잘림) |
| `field_constraints_test.dart` | 본문 16px·터치 타깃 48px·주요 버튼 56px 미만 |
| | 만료 임계값 (D-90/D-30) 회귀 |
| | `StatusPill`이 아이콘 없이 색만으로 상태를 전달하는지 |
| | 러시아어 최장 라벨에서 버튼 오버플로 |

**놓치는 것**: 실제 터치 정확도, 시스템 글꼴 확대 조합, 저사양 기기 성능, 카메라·파일 선택.

### 3-2. 웹 빌드 — 화면 흐름과 API 연동

```bash
# Docker로 (권장)
docker compose up -d mobile-web       # → http://localhost:3300

# 또는 로컬에서
cd apps/mobile-candidate
flutter run -d chrome --dart-define=CARELINK_API_URL=http://localhost:3000/api/v1
```

브라우저 개발자도구에서 **기기 에뮬레이션(402×1096)**으로 보면 FIELD 프레임과 같습니다.

**잡는 것**: 화면 전환, API 연동, 4개 언어 전환, 에러 문구, 빈 목록 상태.
**놓치는 것**: 실제 터치 타깃 체감, 네이티브 저장소(`flutter_secure_storage`는 웹에서
localStorage로 폴백 — **웹 빌드는 토큰 보안을 검증하지 못합니다**), 푸시 알림, 오프라인.

### 3-3. 안드로이드 실기기 — FIELD 규격 최종 확인

```bash
cd apps/mobile-candidate
flutter build apk --release --dart-define=CARELINK_API_URL=http://<호스트IP>:3000/api/v1
# → build/app/outputs/flutter-apk/app-release.apk
```

에뮬레이터에서 호스트는 `10.0.2.2`입니다 (`localhost`가 아닙니다 — 기본값이 그렇게 되어 있습니다).
실기기라면 같은 네트워크의 호스트 IP를 넣고, API의 `CORS_ORIGINS`에 그 주소를 추가하세요.

**여기서만 확인 가능한 것 — 반드시 체크**

- [ ] 40~65세 사용자가 한 손으로 홈 → next_action → 서류 업로드까지 도달하는가
- [ ] 시스템 글꼴을 최대로 키웠을 때 레이아웃이 깨지지 않는가 (앱은 1.6배까지 허용)
- [ ] 4개 언어 각각에서 버튼 텍스트가 잘리지 않는가 (특히 러시아어 — 실측 4.1배)
- [ ] `flutter_secure_storage`가 실제로 Keystore를 쓰는가 (재설치 후 세션이 사라지는지)
- [ ] 저사양 기기에서 목록 스크롤이 끊기지 않는가

### 3-4. 통합 테스트 — 실기기 자동화

`integration_test` 패키지로 실기기에서 흐름 전체를 돌립니다. **아직 작성하지 않았습니다** —
기기 없이 쓰면 검증되지 않은 테스트가 쌓입니다. 기기가 준비된 시점에 아래 흐름부터 쓰세요.

```
로그인 → 역할 선택 → 홈(next_action 1개 확인) → 트랙 선택
     → 서류 업로드 → 여정에서 두 축이 분리돼 보이는지 → 일자리 지원
```

```bash
flutter test integration_test/ -d <device-id>
```

### 개인정보 게이트 수동 확인

이 플랫폼에서 가장 중요한 경로입니다. 배포 전마다 확인하세요.

1. 기관 담당자로 로그인 (검증 **대기** 기관) → `/candidates/{id}` → 이름이 "기관 검증 후 열립니다"
2. 운영자로 기관을 `VERIFIED`로 변경 → 다시 조회 → 이름이 "면접 수락 후 열립니다"
3. 후보자가 면접 요청을 수락 → 다시 조회 → **그 후보자만** 실명·연락처가 열림
4. 같은 목록의 다른 후보자는 여전히 잠겨 있어야 함

4번이 핵심입니다. 승격이 뷰어 단위로 잘못 붙으면 한 명을 수락받은 기관이
전 후보자의 실명을 보게 됩니다.

## 5. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 웹에서 API 호출이 CORS로 막힘 | 출처가 허용 목록에 없음 | `CORS_ORIGINS` 환경변수에 추가 후 API 재시작 |
| 로그인은 되는데 화면이 비어 있음 | 역할이 없음 | 역할 부여 후 **재로그인** (토큰에 박혀 있음) |
| 에뮬레이터에서 API 연결 실패 | `localhost`는 에뮬레이터 자신 | `10.0.2.2` 사용 |
| `devCode`가 안 옴 | `NODE_ENV=production` | 개발 환경에서만 내려옵니다 |
| OTP 재발송이 막힘 | 30초 레이트 리밋 | 기다리거나 다른 번호 사용 |
| 후보자 목록이 비어 있음 | 시드에는 후보자가 없음 | 앱으로 가입하거나 API로 생성 |
