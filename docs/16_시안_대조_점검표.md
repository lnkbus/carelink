# 16. 시안 대조 점검표

> `design/*.dc.html` 8개 파일과 실제 구현을 **화면 단위로** 대조한 결과입니다.
> 2026-08-21 기준. 고친 것과 아직 안 고친 것을 나눠 적습니다.

---

## 0. 왜 이 문서가 생겼나

토큰(색·타이포 값)과 컴포넌트는 시안대로 들어가 있었지만, **화면 구성은
여러 곳에서 시안과 달랐습니다.** 특히 하단 탭·진행 바처럼 IA에 해당하는
것들이 빠져 있었고, 그건 픽셀 문제가 아니라 사용자가 길을 잃는 문제입니다.

대조는 세 가지를 함께 봅니다:

| 출처 | 무엇을 정하나 |
|---|---|
| `design/*.dc.html` | 레이아웃·수치·카피 (인라인 스타일이 곧 스펙) |
| `wireframe/index.html` SCREENS | api · data · states · notes (PRD) |
| `CLAUDE.md` · `docs/07` · `docs/11` | 넣으면 안 되는 것 |

**세 번째가 첫 번째를 이깁니다.** 시안이 그린 것이라도 금지 항목이면 넣지
않고, 그 사실을 화면 주석에 남깁니다.

---

## 1. 시안대로 못 하는 것 — 확정된 금지 항목

시안이 그려진 뒤에 확정된 규칙 때문에 **의도적으로 다르게** 구현한 곳입니다.
시안 파일을 고치실 때 참고하세요.

| 시안 | 어디 | 왜 못 넣나 |
|---|---|---|
| `김영수 어르신` · `82세 · 남성` | SCR-401 · 403 · 505 | 간병사·운영 화면에 환자 실명·나이·성별을 내보내지 않습니다 (§5.2 · docs/11 §3.2). `care_requests`에 컬럼 자체가 없습니다 |
| `식사 후 투약 13:00` · `투약 확인` | SCR-401 · 403 · 404 · 505 | 투약은 의료행위라 서비스 카탈로그에 항목이 없습니다 (§6-2). 자유 입력에서 감지되면 `OPS_REVIEW`로 보냅니다 |
| `당뇨` | SCR-403 | 진단명입니다 (§5.2) |
| `24시간 상주` 선택지 | SCR-303 | 2026-08-21 확정으로 운영하지 않습니다 (§5.12). 서버가 요청 생성을 막습니다 |
| `일당 ₩128,000` | SCR-403 | 금액 계산은 U6(4대보험·퇴직금 반영 단가) 확정 전까지 막혀 있습니다 (§6-8) |
| 간병사 국적 | SCR-304 | 보호자에게 노출하지 않습니다 (§6-21) |

대체물은 전부 **병실 · 필요한 지원 · 주의사항**입니다. 간병사가 알아야 하는
것은 어디서 무엇을 하는가이지 환자가 누구인가가 아닙니다.

### 11·12가 특히 나빴던 이유

백그라운드 잡이 **허공에 돌고 있었습니다.** `care-assignment-sla`는 4시간
미배정을 매 10분 잡아내고 `ticket-sla`는 안전사고 4시간 초과를 잡아내는데,
그 결과가 닿는 화면이 없었습니다. 잡은 도는데 사람이 안 보면 없는 것과
같습니다.

### 13에 딸려 나온 두 개의 버그

퍼널 표를 붙이려다 데이터가 이상해서 파 보니 둘이 나왔습니다.

- **집계 대상이 틀렸습니다.** `jobs.status`(OPEN/DRAFT/CLOSED)를 세고
  있었습니다. 그건 요청의 상태지 사람의 진행 단계가 아닙니다.
  `applications.status`를 **누적 단계**로 바꿨습니다 — 면접까지 간 사람은
  서류 심사도 지났으므로, 각 상태를 그대로 세면 전환율이 실제보다 나쁘게
  나옵니다.
- **응답이 `[{},{},{}]`로 나가고 있었습니다.** `OrgFunnelRowDto`가
  `@Scope('admin','org')`인데 기관 담당자는 평소 `org_masked`만 갖습니다
  (`org`는 역할이 아니라 관계 — 검증 완료 + 후보자의 면접 수락 이후).
  개인정보가 한 톨도 없는 자기 기관 집계라 `org_masked`를 열었습니다.
  **오류 없이 조용히 비어 있었습니다.**

## 3. 아직 안 고친 것

| # | 화면 | 확인해야 할 것 |
|---|---|---|
| A | SCR-501 운영 대시보드 | 시안은 KPI 7칩(매칭 대기·진행 중·기관·사람 확인 필요·차단·이번 달 배치·평균 매칭 소요). 현재 5칩 |
| B | SCR-503 기관 관리 | 재계약률·사건 건수 열. 두 지표 모두 집계 API가 없습니다 |
| C | SCR-508 고용 · 계약 | 월 급여 열 — **금액이라 U6 확정 대기** (docs/17 D-2와 같은 사안) |
| D | SCR-509 품질 · 안전 | 사건 유형별 12개월 추이 · 점검 필요 기관. 추이 집계 API가 없습니다 |
| E | SCR-510 파트너 | 서류 반송률 · 정산 대기 금액 |
| F | SCR-511 코호트 | 코호트 상세의 단계별 인원 바 |
| G | SCR-205 면접 관리 | 통역 배정 정보 · 화상 입장 링크 |
| H | SCR-102 여정 | 5단계 수직 타임라인의 시각 형태(현재는 두 축 목록) |

**A~F는 전부 '집계 API가 없다'가 원인입니다.** 화면만 만들면 빈 열이
생기므로, 지표를 먼저 정하고 만드는 편이 낫습니다.

시안대로 하려면 **결정이 필요한 11건**은 `docs/17_의사결정_대기목록.md`에
따로 모았습니다. 국적 필터 · 간병 비용 표시 · 간병사 실명 · 환자 신원 ·
투약 · 사진 첨부 · 병원 연락처 · 일괄 작업 3종 · 알림 벨 · 정산 탭 ·
역할 스위처.

## 4. 이 문서를 쓰는 법

화면을 하나 고칠 때마다 §3에서 지우고 §2에 옮깁니다. **§1은 지우지 마세요** —
시안과 다른 이유를 잃어버리면 다음 사람이 "시안대로 안 됐다"며 되돌립니다.
