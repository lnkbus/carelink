# 18. 디자인 표준

> **`design/` 시안이 유일한 기준입니다.** 이 문서는 시안을 코드에서 어떻게
> 강제하는지를 적습니다. 값이 시안과 다르면 코드가 틀린 것입니다.
>
> 2026-08-21 기준.

---

## 0. 왜 이 문서가 생겼나

토큰은 시안값이 들어가 있었는데 **레이아웃·스케일·문구가 앱마다 복사돼**
있었고, 이미 갈라져 있었습니다.

| 갈라진 것 | 증상 |
|---|---|
| `globals.css` | 사이드바가 운영 콘솔 216px, 기관 웹 232px |
| 타이포 스케일 | 보호자 웹이 시안의 **상향 스케일** 대신 일반 FIELD 값을 씀 |
| `labels.ts` | 같은 코드가 앱마다 따로 적힘 |
| `Shell` · `NavItem` | 2벌씩 복사 |

복사본은 반드시 갈라집니다. 갈라진 뒤에는 **어느 쪽이 맞는지 아무도 모릅니다.**

## 1. 어디에 무엇이 있나

```
packages/ui/src/tokens/tokens.css   색 · 간격 · radius · 타이포 3단 · 터치 타깃
packages/ui/src/tokens/desk.css     DESK 레이아웃 (셸 · 사이드바 · 표)
packages/ui/src/tokens/field.css    FIELD 레이아웃 (페이지 · 카드 · 타일 · 버튼)
packages/ui/src/labels.ts           공통 오류 문구 (DESK · FIELD 두 레지스터)
packages/ui/src/components/         공용 컴포넌트 9종
packages/field_ui/lib/src/tokens.dart   Flutter 쪽 같은 값 (CL · CLUp)
```

**앱의 `globals.css`에는 그 앱 고유 스타일만 둡니다.** 레이아웃을 복사하지
마세요.

## 2. 타이포 — 3단 스케일

`design/README` §타이포가 원본입니다.

| | DESK | FIELD | FIELD 상향 |
|---|---|---|---|
| 대상 | 운영 콘솔 · 기관 웹 | 후보자 앱 | 간병사 앱 · 보호자 웹 |
| Display | 24 | 26 | 28 |
| Title | 19 | 21 | 24 |
| Subtitle | 15 | 17 | 19 |
| Body | 14 | 16 | **18** |
| Caption | 12 | 14 | 16 |
| Micro | 10.5 | **없음** | **없음** |
| 토큰 | `--cl-*` / `CL` | `--cf-*` / `CL` | `--cu-*` / `CLUp` |

**상향 스케일이 따로 있는 이유**: 같은 FIELD여도 후보자는 조용한 곳에서
시간을 들여 보고, 간병사·보호자는 40~65세이고 병실 앞에서 한 손으로 급하게
봅니다. 한 벌만 두면 어느 한쪽은 반드시 시안과 어긋납니다.

**FIELD에 Micro가 없습니다.** 12px 미만은 고령 사용자에게 존재하지 않는
텍스트라, 토큰 자체를 정의하지 않았습니다 — 쓸 수 있게 두면 언젠가 쓰입니다.

> Caption 상향은 시안이 `15~16`인데 **16**을 골랐습니다. `CLAUDE.md` §9의
> 16px 하한을 함께 만족하는 값입니다.

### 강제 장치

`packages/ui/test/tokens.spec.ts`가 **웹과 앱의 값이 같은지** 대조합니다.
한쪽만 고치면 테스트가 깨집니다.

```bash
pnpm --filter @carelink/ui test
```

## 3. 터치 타깃

| | 값 | 어디 |
|---|---|---|
| DESK | 32px+ | 표 행 액션 · 필터 칩 |
| FIELD | 48px+ | 모든 누를 수 있는 것 |
| 주요 액션 | 64px | 화면의 핵심 동작 (신청·저장·출근 체크) |
| 히어로 | 76~88px | **화면에서 가장 큰 하나.** 앱 76 · 웹 88 |

히어로는 화면당 **하나뿐**입니다. 둘이면 어느 것이 주된 동작인지 사라집니다.

---

## 4. 색 — 시그널은 3개뿐

`signal`(초록) · `flag`(앰버) · `alert`(적). **상태를 늘릴 때 색을 늘리지
마세요.** 아이콘+텍스트로 구분합니다 — 색만으로 전달하는 구현은 반려 대상이고,
색각 이상 사용자에게는 그 상태가 존재하지 않습니다.

액션색은 밝은 블루(`#2F6BFF`)입니다. docs/09 §5.1의 원본 저채도 팔레트
(`#1F6F5C`)는 쓰지 않습니다 — 시안에서 교체됐습니다.

---

## 5. 문구 — 레지스터가 둘

같은 오류 코드라도 읽는 사람이 다릅니다.

| | 대상 | 원칙 | 예 (`COMMON_INVALID_TRANSITION`) |
|---|---|---|---|
| **DESK** | 운영자 · 기관 담당자 | 하루에 수십 번 본다. 간결하게 | "허용되지 않는 상태 변경입니다." |
| **FIELD** | 보호자 · 후보자 · 간병사 | 처음 보고 급하다. **다음 행동까지** | "지금은 할 수 없는 동작입니다. 화면을 새로고침해 주세요." |

이 차이는 실수가 아니라 규칙입니다. 하나로 합치면 한쪽이 반드시 나빠집니다.

```ts
export const errorLabel = makeLabeler('desk', ERROR_DICT);  // 앱 고유 코드만
```

공통 코드(`COMMON_*` · `IAM_*` · `NETWORK`)는 `packages/ui`에서 옵니다.
앱 사전에 다시 적지 마세요.

**모르는 코드는 코드 그대로 보여 줍니다.** 빈 문자열을 주면 화면이 비고,
그러면 무슨 일이 일어났는지 아무도 모릅니다.

## 6. 넣으면 안 되는 것

시안에 그려져 있어도 넣지 않습니다. 이유는 `docs/16` §1에 있습니다.

- 환자 실명 · 나이 · 성별 · 진단명 (간병사·운영 화면)
- 간병사 실명 · 국적 (보호자 화면)
- 투약 등 의료행위 항목
- 24시간 상주 선택지
- 확정되지 않은 금액

**시안이 규칙을 이기지 않습니다.** 대신 자리는 남기고 무엇을 기다리는지
씁니다 — 자리를 지우면 결정이 난 뒤 레이아웃을 다시 짜야 합니다.

---

## 7. 새 화면을 만들 때

1. `design/*.dc.html`에서 해당 화면을 **연다.** 인라인 스타일이 곧 스펙입니다.
2. 트랙을 정한다 — DESK / FIELD / FIELD 상향.
3. 토큰과 공용 컴포넌트로 짠다. **새 크기·새 색을 만들지 않는다.**
4. `docs/16` §1의 금지 항목에 걸리는 게 있으면 자리만 남기고 주석에 이유를 쓴다.
5. 끝나면 `docs/16` 표를 갱신한다.
